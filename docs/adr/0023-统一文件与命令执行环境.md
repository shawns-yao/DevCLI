# ADR 0023：统一文件与命令执行环境

状态：已接受，2026-10-16。

## 问题

命令已有主机、Docker 和 Windows 隔离后端，文件工具却直接调用 Files。只替换命令服务不能更换完整执行环境，也容易遗漏隔离工作区的恢复与归并路径。

## 决定

- ToolContext 暴露唯一 ExecutionEnvironment，ToolRegistry 装配它。命令的校验、审批环境判断和执行从该环境取得既有 CommandExecutionService；删除单独的命令服务字段及注入入口。
- 文件读取、分页输入流、目录、glob/grep 候选与内容、写入、删除预检和补丁应用走同一环境。权限和内容审查仍属于工具运行时，不下放到文件后端。
- 默认 LocalExecutionEnvironment 复用 Files、ProjectFileLister 和 PatchSet；命令仍由既有服务选择主机、Docker 或 Windows 后端。Docker 挂载工作区，文件视图与命令看到的目录一致。
- 环境按调用传入的已批准绝对路径或命令请求根目录操作，不持有可变的当前项目。隔离 fork 共享后端，传入自己的工作区路径；恢复补丁在子环境应用，最终提交由父环境在项目提交锁内应用。
- Path 表示供路径策略、版本账本、LSP 和 PatchSet 采集使用的本地工作区视图。任何后端都必须在调用返回前保证视图与执行侧一致，并实现相同的补丁冲突及原子提交语义。远程传输、物化与服务配置属于具体后端，本轮不增加未配置的远程实现或配置开关。

## 保留边界

IsolatedWorkspace 继续负责本地工作区生命周期、基线和变更采集。ContextVersionLedger 继续校验该视图；PatchSet 继续实现全量冲突预检、权限保留、原子应用及失败回滚。它们是事务协调与本地视图设施，不是另一套模型文件工具。长期记忆、会话数据库、工具产物和凭据存储不属于项目文件环境。

## 验证

定向测试从真实 ToolRegistry 入口验证后端接线、分页、编辑、目录、搜索、命令及删除；使用记录型本地环境核对工作区路径和父项目提交。隔离写入在提交前不可见，外部修改仍导致冲突。敏感内容审批、路径保护、写范围和编辑后 LSP 由已有回归覆盖。命令测试用替身，不据此宣称 Docker 或远程部署已验收。
