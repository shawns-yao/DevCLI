# ADR 0025：机械质量门禁与存量职责清理

日期：2026-10-17。状态：已采纳。

## 背景

静态检查原先只报告，版本与本机构建环境分散，超大类和无入口的旧 Plan 路径增加交接成本。目标是可验证的代码质量，不扩展企业产品功能。

## 决策

- Maven Wrapper 锁定 3.9.11 和发行包哈希；构建、测试要求 JDK 21，生产使用 release 17。Banner 和产物统一从 POM 取版本。
- CI 在 Linux、Windows 执行 quick 和全量。SpotBugs 拒绝新增告警；基线仅包含 35b3951a 实测的具体实例，不扩大豁免。
- Spotless 只约束行尾与结束换行，保持现有布局；JaCoCo 输出独立批次报告，不设比例门槛。
- Dependabot 每周检查；Dependency-Check 使用 NVD 官方压缩 feed，已知漏洞及扫描设施失败均阻断。
- 所有生产 Java 文件最多 1000 行，不设存量例外。拆分视图渲染、调度、结构初始化和文件持久化等真实职责，保留状态与锁的所有权。
- 删除已无生产入口的旧 Plan 实现及专用测试；保留有调用者的 SubAgent、显式索引和检索。
- 固定 20 个官方 Multilingual Java 原始任务，仅经实际 `-p` 入口运行，模型执行与官方评分分开；本轮不付费运行。
- 历史生成产物停止跟踪，保留本地数据；根规范只保留规则和导航。

## 影响与证据

Wrapper、固定基线和公开原文样本增加必要文件体积，旧执行路径与生成产物清理减少源码和跟踪噪音。基线不是告警清零，覆盖报告也不代表效果验收；验证结果记录在实施计划，远端 CI 与付费模型任务不得按配置存在宣称通过。

旧 checkpoint 协议与 PatchSet 生命周期不变。Runtime 结构迁移只把“列已存在”和 SQL 失败分开，不新增表或兼容协议。用户未来任务按最新指示先实现，再决定测试时机。
