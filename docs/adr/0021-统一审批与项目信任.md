# ADR 0021：统一审批与项目信任

状态：已接受，2026-10-16。替代 ADR 0006 的主机强制逐次审批、ADR 0013 的 auto 规则让位，以及 ADR 0020 的白名单命令规则限制。

后续修订：ADR 0026 将主 Agent 命令默认置于离线沙箱；主 Agent 脱离沙箱必须逐次确认，项目窄规则不再免除这次确认。以下保留当时决策。

## 问题

主机命令绕过工具 HITL 阶段，在后端另行审批；auto 的明确规则与项目编辑仍会额外调用分类器。两套路径造成规则和模式语义不同，分类器持续阻止也没有交回用户的上限。

## 决定

- 模型调用和内部命令 API 都进入工具管线；语义与后端硬策略检查先于审批。删除 reviewHostCommand 和主机早退分支。
- 所有模式先执行硬策略、hard_deny、soft_deny、allow。soft_deny 交给用户；auto 不重复分类明确 allow。auto 忽略过宽的命令规则，主机命令在所有模式下只接受窄规则；被丢弃的规则不进入分类器。Shell 复合语义不由前缀规则授权。
- auto / acceptEdits 接受普通项目编辑。删除阈值、命令删除、回滚、敏感浏览器及破坏性 MCP 的逐次确认先于任何规则或模式放行。
- 交互入口首次询问项目信任，用户侧 `~/.devcli/project-permissions.json` 按真实项目路径保存决定及该项目的 permissions.allow。未信任项目的主机命令逐次确认；无交互入口只读取已有决定。隔离 fork 继承其逻辑主项目的授权；切换项目不继承旧项目规则。Skill 信任保持独立。
- 信任后窄命令规则可在 default / auto / dontAsk 直接放行；auto 可分类未决主机命令。信任不覆盖硬拒绝，也不提供操作系统隔离。用户须接受构建插件和脚本可能执行任意主机代码的代价。
- 审批 `[p]` 保存当前完整命令前缀，不截成可执行程序级通配。展示规则及项目路径；强制单次确认、未信任项目、解释器通配、复合 Shell 和敏感命令不提供保存。写入失败不执行命令。规则只对该项目有效；撤销时由用户删除规则或更改 trusted。
- 删除 `/grant commands`；`/grant all` 只授予写入。已确认计划内部的临时命令授权继续受作用域、项目信任与硬策略限制。
- 分类器连续阻止 3 次或累计阻止 20 次后切换 default，并询问当前调用。成功判定只重置连续阻止；故障仍拒绝并保留原失败阈值。根注册表与 fork 共享计数，手动切换模式重置。

## 验证边界

定向测试使用真实工具入口、临时文件与授权存储，替换模型判定和命令后端；真实进程测试继续覆盖取消、期限及未批准不执行。quick 与终端兼容回归验证已有协作路径。不据此宣称分类器判定质量或沙箱安全性；主 Agent 默认主机命令沙箱不在本次范围。
