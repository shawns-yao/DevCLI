# Git 工作树共享项目记忆

## 背景

项目记忆按当前目录生成项目键，同一仓库的关联工作树和子目录会分散到不同目录。切换工作树后，已保存的构建约定和项目事实无法复用；直接更换项目键又会使旧主题不可见。

## 决定

- 使用已有 JGit 依赖识别最近仓库及其 common directory，再解析主工作区根路径；关联工作树和仓库子目录共用该路径的项目键。嵌套独立仓库使用自己的根路径。普通目录或 Git 元数据不可用时保留请求绝对路径。
- `LongTermMemory` 在项目绑定时固定解析后的路径，读写和清空使用同一作用域。全局记忆目录、主题格式、相关性选择、预算和记忆工具审批继续复用现有实现。
- 绑定旧路径时，仅迁入该路径原有目录中的主题 Markdown，按原相对路径复制并保留内容与文件属性。扫描深度与现有主题扫描器一致，索引不迁入，读取时由主题重建。
- 已存在同名目标时不覆盖；内容不同计为冲突，源文件保留用于人工核对。状态分别显示迁入、冲突和失败数量。
- 每个旧来源处理成功后写入独立完成标记，冲突计数保留在标记中。遗忘或清空主题不会删除标记，避免旧源内容再次导入；读取或复制失败时不完成迁移，修复后再次绑定可重试。

## 关键取舍

- 共享项目事实优先于按分支隔离；分支差异应写明适用条件，不把关联工作树当成独立项目。
- 只迁移当前绑定的旧来源，不扫描全部历史项目目录或尚未打开的工作树，避免根据目录名称猜测项目归属。
- 同名冲突保留共享版本，不按时间自动覆盖或调用模型合并。用户需要核对保留的源文件后显式保存。
- 完成标记使迁移一次性生效；完成后新加入旧目录的主题不再自动迁入。

## 后果

切换关联工作树后可直接查看、保存和更新同一份项目记忆。旧源文件保留，占用空间不会自动回收；Git 主工作区移动后仍需按新路径处理记忆。当前没有新增跨进程写入事务，也没有开放子 Agent 的长期记忆权限。

定向测试通过真实 Git 仓库、关联工作树、记忆工具执行管线和 Markdown 存储检查共享、隔离、迁移、冲突保留及删除后不重复导入；不衡量模型召回效果。
