# ADR 0022：会话事件日志与上下文视图分离

状态：已接受，2026-10-16。

## 问题

Runtime 已有追加事件表和统一执行循环，但工具结果先裁剪再发事件，CLI 只在整轮结束后补写窗口。恢复只选已完成回合，无法完整读取裁剪前的返回结果，也会丢失未完成回合的事实。

## 决定

- 复用 `runtime.db` 的 runtime_events，不增加第二套日志、配置开关或执行循环。事件只追加；checkpoint、统计和模型窗口都是投影。
- 工具管线在内容审查后保留返回结果，在退出尺寸治理后发布 `tool.result.recorded`。记录正文、图片、修改资源及生产者已有产物引用；外层记录阶段也覆盖参数、权限等提前返回。日志写入失败向上抛，不转换成可重试工具错误。
- `tool.results` 记录批次窗口预算裁剪前的对账结果，`model.message` 记录实际追加消息。模型调用消费 `ModelContextView` 从快照事件生成的窗口，不直接持有可变历史列表。历史列表只作为压缩器和既有运行投影的工作视图。
- `model.context(iteration=0)` 保存导入或初始化视图，实际请求快照保存当前迭代号。压缩追加新快照或现有压缩 checkpoint，不删除原始消息事件。首次导入的旧窗口只代表当时实际保存的内容，不能冒充完整原文。
- `ConversationReplay` 独立负责当前分支可见事件的窗口和原文重放；原文优先使用裁剪前的工具结果。恢复包含未完成和失败回合，已记录结果可补齐配对，缺失结果只在窗口中标为状态未知，原文不伪造工具结果。恢复不执行工具，也不重放副作用。缺失结果的长正文只恢复有界预览。
- CLI 和 `-p` 共用 `ConversationTurnRecorder` 实时记录，删除 CLI 结束后补写历史的旧路径。Runtime API 继续使用同一发布器实时写入；发布器固定 thread/branch/turn，后台事件不跟随活动分支切换。真实用户输入独立于窗口注入内容恢复。
- 子 Agent 仍复用执行循环，以 `agent.event` 封装身份和自己的事件，不进入父窗口；父模型只消费最终委派报告。trace 只保留结构字段，不保存原文；可选 JSONL 归档不参与恢复。
- 从 RuntimeThreadStore 提取上下文重放与会话统计投影，存储类保留 SQL、分支可见性和检查点校验。

## 边界

完整返回结果指工具生产者返回、经过内容审查的结果。命令流式输出原有配额、不完整标记及产物引用继续有效；不扩容生产者输出。旧日志中已丢失的正文和图片无法补回。恢复模型上下文不等于恢复文件系统，也不保证中断的外部操作已经完成。

本次不增加新的压缩算法、记忆层、沙箱后端或编排机制。原始事实可以重新生成视图，但不会据此宣称原有摘要具有相同质量。

## 验证

定向测试使用真实 AgentExecutionEngine、工具注册表和临时 SQLite，模型输出由测试替身提供。覆盖大结果裁剪前记录、图片往返、压缩前原文保留、未完成工具配对、子 Agent 隔离、分支绑定及执行中保存。quick 与终端兼容回归检查既有协作路径；这些结果不代表真实模型任务能力评测。
