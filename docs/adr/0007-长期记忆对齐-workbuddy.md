# 长期记忆对齐 CodeBuddy：作用域物理隔离、主题 Markdown 与可审计生命周期

- 状态：已接受并实施
- 日期：2026-09-21
- 取代：ADR 0002 中的旧记忆卡、旁路计数和运行时队列设计

## 背景

旧长期记忆同时包含 Markdown 记忆卡、旁路计数、证据审核、Curator、
晋升队列、确认票据、冲突取代和多种检索规则。同一条记忆的作用域由元数据表达，
候选截断后才过滤项目，存在其他项目记忆挤占当前项目候选位置的风险。

本次参照的是腾讯 CodeBuddy Code 与 WorkBuddy 公开文档中已运行的产品行为，
不复制闭源实现，也不把同名开源 GPL 项目的代码并入商业项目。

公开参照：

- [CodeBuddy Code 记忆](https://www.codebuddy.cn/docs/cli/memory)：全局/项目 Auto Memory、`MEMORY.md`、主题文件和记忆类型。
- [CodeBuddy Code 设置](https://www.codebuddy.cn/docs/cli/settings)：`relevanceSelection` 默认开启，`memoryExtraction` 默认关闭。
- [WorkBuddy 记忆](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Memory)：记忆可查看、编辑、删除和停用，相关记忆进入后续会话。

## 决定

### 1. 作用域由目录表达

```text
<memoryRoot>/
├── global/
│   ├── MEMORY.md
│   └── <topic>.md
└── projects/<projectKey>/memory/
    ├── MEMORY.md
    └── <topic>.md
```

- `global` 为跨项目用户偏好与参考知识。
- `project` 只在当前项目可见；存在活动项目时默认写项目作用域。
- `projectKey` 由规范化绝对路径压缩得到。
- 传入未知作用域时拒绝写入，不默认扩大为全局。

### 2. 每个主题一个 Markdown 文件

frontmatter 权威字段：

```yaml
---
name: 项目构建方式
description: DevCLI 的构建与定向测试命令
type: project
created_at: 2026-09-21T00:00:00Z
updated_at: 2026-09-21T00:00:00Z
expires_at: 2026-10-21T00:00:00Z
revision: 2
---
```

`type` 只允许 `user` / `feedback` / `project` / `reference`。`expires_at` 可选，
其余时间与修订字段由写入路径维护。旧主题文件缺少字段时，
以文件修改时间和修订 `1` 兼容读取。

### 3. 冲突与修订

- 同作用域、同主题、同内容：`UNCHANGED`，不刷新时间。
- 同作用域、同主题、不同内容的自动写入：`CONFLICT`，保留原文。
- 用户显式保存不同内容：覆盖该主题并将 `revision` 加一。
- 全局与项目同名但内容不同：两份文件都保留，召回使用项目版本，
  `MEMORY.md` 注入段显示作用域冲突。

冲突是由当前文件派生的视图，不另建冲突数据库或状态机。

### 4. 有效期

- 无 `expires_at` 的记忆长期有效。
- 到期后保留原文和审计导出，但排除于 `MEMORY.md`、候选集、关键词检索和 LLM 选择。
- 到期不依赖背景清理线程；读取时以当前时钟判定，避免进程停止导致失效。

### 5. 索引与召回

- 每个作用域的 `MEMORY.md` 可从主题文件重建，不是第二权威。
- 注入最多前 200 行或 25000 字节，超出显式标记截断。
- 索引始终提供目录视图；LLM 选择器默认开启，输入清单最多 4096 tokens，输出最多选 8 条并读全文。
- 选择器只接受**实际发送给模型**的有界候选清单中的文件名；被截断的候选不在结果白名单内。调用、JSON 解析或白名单校验失败时不注入全文。
- 同一会话不重复注入同一主题全文。

### 6. 写入安全与自动提取

- `/save` 与 `save_memory` 为明确写入入口。`save_memory` 支持主题、描述、类型、作用域和有效天数。
- 普通用户消息和任务收尾不自动落盘，与 CodeBuddy 公开设置中 `memoryExtraction=false` 一致。
- 内容命中凭据、账号、身份证、手机号、银行卡、地址或医疗信息时拒绝写入，
  要求用户脱敏后重试。这是 DevCLI 的产品安全保留项，不因对齐竞品而删除。

### 7. 旧版记忆迁移

- 启动时扫描旧版 `records/**/*.md`，把合法卡片幂等复制到全局主题目录。
- 目标文件名由旧记录 id 的 SHA-256 摘要确定；重复启动不会生成副本。
- 全部旧卡片处理成功后在记忆根目录写一次性完成标记；后续 `LongTermMemory` 构造不再重复扫描和解析保留的旧源文件。存在损坏卡片或标记写入失败时不落标记，下一次继续重试。
- 代价必须写明：迁移整体由「每次启动都可重入」变成**一次性**（复制步骤本身仍按摘要幂等，重复复制不产生副本）。落标记后新加入 `records/` 的卡片不会被补迁；标记在记忆根目录而迁移产物在 `global/`，因此清空全局记忆不会重置标记，被清掉的 `legacy-*.md` 不会重新导入。旧格式已无写入方，且清空全局记忆是用户显式动作，这两条在当前代码路径上不可达——但它们是有意的取舍，本条不再声称整个迁移可重入。
- 旧文件不删除。旧格式没有可靠的项目归属，因此不猜测项目作用域。
- 损坏卡片逐条跳过并记录告警，不阻断其他记忆加载。

## 删除的旧路径

删除 Curator、晋升队列、确认票据、Evidence 审核态、Hot Cache、旁路计数、
旧关键词打分器、Supersede 状态机和 Organizer。`/memory pending|confirm|reject` 保留兼容提示，
不再操作队列；`/memory organize apply` 改为从权威 Markdown 重建索引。

## 边界

- 本期不实现团队记忆，因为当前没有用户身份与共享后端。
- 不自动合并跨作用域冲突；项目覆盖只影响召回优先级。
- 不评估 CodeBuddy 闭源实现的内部正确性；只对齐可从公开文档验证的产品契约。

## 验证

- 定向测试覆盖：物理作用域、自动冲突拒绝、显式修订、过期审计/召回隔离、
  跨作用域覆盖提示、旧版卡片迁移、敏感内容拒绝、工具参数传递和显式写入通知。
- 索引注入的预算裁剪单独覆盖：用例先断言未裁剪索引确实超出本轮预算（保证样本有区分度），
  再断言注入结果不超过预算且带截断提示——索引自身上限比预算大一个数量级，
  不裁剪会让「记忆预算」这个配置项对索引完全失效。
- 清空的作用域语义单独覆盖：项目会话里执行默认清空后项目记忆消失、全局记忆文件仍在，
  并提示如何显式清另一作用域；未绑定项目时默认退化为清全局并明确告知；未知作用域被拒绝。
- 选择器清单覆盖 200 条大描述候选，验证输入不超过 4096 tokens，且模型不能猜中被截断的文件名；迁移测试验证完成后不再解析保留的旧源卡片。
- `mvn.cmd -q -Pquick test` 执行 2082 项，记忆相关失败已清零；剩余 3 项为委派证据截断标记
  （`AgentDelegationTest`）、主机命令测试前置条件（`AgentGovernanceRegressionTest`）和
  符号链接拒绝（`DeleteFilesApprovalTest`），三项都能用 `-Dtest=<类名>` 单独复现，
  且都在本 ADR 改动链路之外。同批次里 `TerminalCapabilitiesTest`（终端能力探测）与
  `RuntimeApiServerTest`（`NoClassDefFound`）曾在并发构建下失败、单独复跑通过，属环境波动；
  因此单次 `-Pquick` 的失败清单必须逐项单独复跑，才能区分稳定失败与波动。
- 未使用真实模型评估相关性选择质量；当前验证不构成公开权威评测。
