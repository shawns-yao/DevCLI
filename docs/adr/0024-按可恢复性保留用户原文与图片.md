# ADR 0024：按可恢复性保留用户原文与图片

状态：已接受，2026-10-16。

## 问题

原实现每轮清掉全部历史图片，只留下无法重读的通用占位。摘要的视觉描述回调没有调用方。工具角色的实际请求只发送 content，估算却读取 contentParts，折叠后仍保留原分段。摘要保留完整近期轮次，但没有单独保留更早的高密度用户原文。

## 决定

- 统一执行循环在请求前处理图片，删除主 Agent 和 SubAgent 的全量旧图剥离路径。内联像素在现有 runtime 目录的 images 子目录按 SHA-256 归档，另存 MIME、尺寸和描述。无需新配置，沿用 DEVCLI_RUNTIME_DIR / devcli.runtime.dir。
- 当前模型支持视觉时，对每份像素生成一次有界客观描述并落盘缓存；调用计入共享 Token 预算及 model.context/model.usage 请求审计。失败直接退出，不静默生成猜测或重试；不支持视觉的模型只归档并明确描述缺失。
- 模型窗口保留最近三张图片，更早的像素用路径、尺寸和描述替换。仅追加 context.projection，旧事件和原始像素不变。描述是模型观察，不是用户授权或执行证据。
- read_image 仅重读受控归档中的精确哈希路径，并核对载荷哈希。不扩大 read_file 的项目围栏，不提供目录枚举。重新打开的图片仍进入同一预算与回收规则。外部 URL 只保留来源并标明未缓存像素，不在压缩中隐式增加网络请求。
- 摘要输入直接使用引用中的描述，删除未接线的 setImageSummarySupplier。checkpoint 的去像素投影也保留同一引用；恢复新日志仍以追加事件为准。
- 在完整近期轮次之外，摘要与失败截断按剩余预算保留旧用户原文，上限约 20k Token，按最近消息优先、整条保留。包括 USER、STEERING、FOLLOW_UP，排除内部注入和工具图片说明；更早约束继续由摘要及语义守卫保护。手动 keep=0 取消完整轮次保留，用户原文仍按此预算保留。
- 工具角色按实际发送的 content 文本估算；结果折叠去掉 contentParts，保留调用与结果配对。原文落盘且替换后的真实估算更小时才提交占位。

## 边界与验证

runtime/images 是会话附件归档，不是长期记忆，不提交 Git；应与会话数据一同保留，删除归档后引用无法保证重读。URL 及旧日志中从未保存的像素不承诺可恢复。

验证覆盖真实 Agent 循环与临时 SQLite 重放、描述缓存和预算、最近三张、重读围栏、摘要引用、用户来源保留、工具配对及 Anthropic 实际请求捕获。模型由测试替身提供，不宣称描述质量或真实模型任务能力已经验收。
