# ADR 0029：记忆元数据与 MCP 绑定复核

状态：已接受，2026-10-17。补充 ADR 0027，不改变记忆层级、模型调用或审批模式。

## 已核对的缺口

- save_memory 经 MemoryManager.storeTopic 写入主题。原检查只扫描正文，主题名和描述却会进入主题文件及每轮记忆索引，可能持久化未获允许的敏感内容。
- MCP 根注册表更新客户端或重新发布同名同描述工具时，旧 fork 仍保存旧 invoker。原守卫只比较描述，无法区分旧连接与新连接。本地只读授权更新也只修改策略目录，没有刷新已发布的工具效果合同。
- Skill 相似提示要求双方至少四个词项，因此完全相同的短描述没有提示；原分词表达式可能把拉丁字母后紧邻的汉字吞入同一个词。

## 决定

- 主题名、描述和正文合并进入既有敏感文本检查，在持久化、索引重建和保存通知前拒绝。复用现有识别规则，不新增检测器，不回传原文；不扫描或重写已有主题。
- MCP 守卫绑定完整的 McpRegisteredTool 实例。根目录重新发布执行器后，旧请求与旧 fork 返回 STALE_TOOL_SNAPSHOT，不能继续调用旧客户端；新请求取得新绑定。同一描述重连不等同于第三方定义变化，不新增定义审批。
- 本地 MCP 信任策略变更在注册表锁内重新发布现有工具合同与执行绑定；撤销只读授权立即恢复保守能力，deniedTools 移除已注册工具，同时清除该服务的批量批准。旧 fork 必须重新创建；已被移除的工具需重新发现后才可能注册，不保存第二份被禁用工具目录。
- Skill 的非空描述经大小写与空白归一后完全相同时直接提示；其他词面相似仍沿用至少四个词项及 Jaccard 0.75。汉字与非汉字词分开切分，不修改排序、加载和 allowedTools 并集。

## 边界与验证

工具数据的 UNTRUSTED 标记仍是模型请求视图，不能替代能力、审批或沙箱，也不能保证自然语言指令一定被忽略。此轮复核保留已有来源标签格式调整，不把其他未提交改动混入功能提交。

首次实现时按用户要求只编译源码和测试源码，未运行测试或启动模型、MCP 服务。敏感模式检查不能识别所有秘密，执行绑定检查也不能保证服务端实现与描述一致。
