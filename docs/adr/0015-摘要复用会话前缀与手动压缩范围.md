# 摘要复用会话前缀与手动压缩范围

## 背景

独立摘要请求改变 system 与工具定义，难以复用已有模型请求的缓存；自动 Token 阈值也不能表达用户主动保留指定原文轮次的意图。现有事实闸门、滚动摘要与工具配对协议必须继续复用。

## 决定

- 首次全量摘要与首次预摘要优先保留待压缩的旧消息前缀与原 system，冻结工具定义，在末尾追加结构化协议；保留区不进入请求。完整请求必须预留模型输出空间；超出预算、工具调用响应或摘要协议无效时回退独立摘要。所有返回响应均计入 Token 预算。
- 摘要仅直接调用 `LlmClient`，不经过执行引擎，不能执行工具。保留原工具选择行为以保持缓存前缀；模型返回的工具调用不作为摘要使用。
- 增量摘要继续使用旧摘要索引和新增原文，避免将稳定事实再次交给模型重写。
- `Agent.compactHistoryNow` 与 `ConversationHistoryCompactor.compactNow` 提供主动入口，CLI `/compact [--keep N]` 默认保留最近 1 轮，N 可为 0。切分只发生在主用户轮次边界；未完成工具批次拒绝操作。
- 手动入口复用事实校验与投影，绕过自动触发及冷却，不启动紧急截断；只有 Token 减少且最终预算通过才替换窗口。成功窗口沿用会话持久化格式。
- Anthropic 自动缓存默认开启，提供兼容端点关闭开关，按官方响应字段汇总完整输入及缓存读取 Token。

## 关键取舍

- 独立摘要更容易服从专用 system，但会损失缓存复用机会，因此保留为有界回退路径。
- 禁用请求中的工具选择可以阻止模型生成工具调用，但改变选择参数会影响消息缓存。当前工具均由本地执行管线调度，摘要路径没有执行入口，因此保留定义并丢弃工具调用响应。
- 任意消息或中间片段的切分会引入多摘要位置和工具配对治理；当前选择旧前缀压缩加近期轮次保留，延续单一滚动摘要结构。

## 后果

前缀请求额外包含原 system 与工具定义，因此服务端缓存未命中时输入费用可能增加。缓存收益、真实摘要保真度与付费模型兼容性需要另行评测；本地 HTTP 夹具只能验证实际 Agent、请求序列化、响应统计和压缩提交链路。详见 [压缩设计](../context-compaction-design.md)。
