# 取消原语下沉到叶子包，断开 `llm` 对 `runtime` 的依赖

## 背景

`src/test/java/com/devcli/PackageBoundaryTest.java` 扫描 `import com.devcli.X.` 发现多个历史循环依赖，其中一条的根因很明确：

**`llm` 包只为了 `CancellationToken` 和 `CancellationContext` 两个类，依赖了整个 `runtime` 包。**

这两个类当时放在 `com.devcli.runtime`，而 `runtime` 是高层包（`AgentSessionRuntime` 依赖 `agent`、`llm`、`tool`、`memory`）。于是：

```
llm ──(仅需取消原语)──> runtime ──> agent / tool / memory / ...
```

`llm` 是模型客户端层，按分层意图它只应认识配置与运行时原语。但因为它指向了 `runtime` 这个高层包，`FORBIDDEN` 表里刻意没有把 `runtime` 写进 `llm` 的禁用列表——**写进去检查就会长期为红，反而失去信号价值**。

## 决定

把取消与运行上下文原语**下沉到新的叶子包 `com.devcli.concurrent`**，包含三个类：

| 类 | 行数 | 原位置 |
| --- | --- | --- |
| `CancellationToken` | 126 | `runtime` |
| `CancellationContext` | 87 | `runtime` |
| `RunContext` | 95 | `runtime` |

三个类**都没有任何 `com.devcli` 依赖**（只用 JDK），因此可以放在最底层而不引入新的环。

随之把 `runtime` 写进 `llm` 的 `FORBIDDEN`，让检查真正覆盖这条边界。

## 关键取舍

**为什么必须三个一起下沉。** `llm` 同时依赖 `CancellationToken` 和 `CancellationContext`，而 `CancellationContext` 引用 `RunContext`。只搬 `CancellationToken` 无法断开依赖。

**为什么新建 `concurrent` 而不是放进现有叶子包 `util`。** `util` 当前放的是通用工具（`AnsiStyle`、`JiebaSegmenterFactory`、`TerminalMarkdownRenderer`、`VectorMath`）。取消原语是一个具体关注点，不是通用工具；`util` 容易被当成杂物抽屉，语义边界会随规模模糊。项目其余包名也倾向语义化（`policy`、`hitl`、`snapshot`、`lsp`）。

**为什么不用 `com.devcli.context`。** 该包已存在，但装的是 LLM 上下文管理（`ContextInputSnapshotStore` / `ContextProfile` / `TokenUsageFormatter`），且**依赖 `llm` 与 `util`**——不是叶子包，放进去会造出 `concurrent → llm` 的新环。

**`CancellationContext.bind` / `restore` 由包级私有改为公开。** 这两个方法原本只被同包的 `AgentSessionRuntime` 调用（把运行上下文绑定到工作线程）。跨包之后必须公开。这**扩大了公开 API**，是本次变更的真实代价；接受它的理由是：这两个方法本就是「把上下文传播到另一线程」的正当原语操作，不是调用方的实现细节，且 `AgentSessionRuntime` 确实需要它。

**不通过放宽检查来掩盖。** 按 `AGENTS.md` 第 363 行的要求，包边界违规不得靠删检查、放宽规则或加忽略项来掩盖。本次是**真正下沉原语**，不是放宽断言。

## 后果

- **`llm → runtime` 已断开**，`PackageBoundaryTest` 新增断言并当前为绿。这条边界此后受机械保护。
- **其余历史循环依赖仍在**：`agent ↔ runtime`、`tool ↔ runtime`、`tool ↔ mcp`、`tool ↔ rag`、`tool ↔ workspace`、`hitl ↔ render`。它们各有不同根因，**本次不处理**，仍在 `TODO.md` 中。
- 新增顶层包 `com.devcli.concurrent`，已加入 `PackageBoundaryTest.LEAF_PACKAGES`（不得依赖任何其他 `com.devcli` 顶层包），由检查保证它不会长出反向依赖。
- 测试随源码迁移：`CancellationContextTest`、`RunContextTest` 从 `runtime` 测试包移到 `concurrent` 测试包，与源码包对齐。
- 影响 22 个主源码文件与 9 个测试文件的 import。
