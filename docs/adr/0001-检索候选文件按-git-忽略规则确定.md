# 检索候选文件按 git 忽略规则确定

## 背景

`grep_code` 原先只按硬编码的 `SKIP_DIRS` 遍历目录，不读 `.gitignore`。在本仓库实测：扫描 **597,333 个文件、超过 10 分 50 秒仍未完成**，而 `git ls-files --cached --others --exclude-standard` 认为相关的只有 **857 个**。多出的部分几乎全是被忽略的目录（`Temp` 524,895、`Data/raw` 75,501、`Test` 51,368、`cc` 3,509、`learn-agent` 1,504、`live` 1,097）。

更根本的问题是同一概念在四处各写了一份，且互不相同：

| 位置 | 与其它三处的差异 |
| --- | --- |
| `GrepToolProvider.SKIP_DIRS` | 独有 `.venv`、`.codegraph` |
| `CodeIndexPathPolicy.EXCLUDED_DIRECTORIES` | 独有 `.next`、`.nuxt`、`.cache`、`.pytest_cache`、`.mypy_cache` |
| `WorkspacePathPolicy.EXCLUDED_ROOTS` | 独有 `Temp`、`Log` |
| `SnapshotConfig` | 只列了 `node_modules` 等少数几项 |

没有任何一处读 `.gitignore`。这意味着**用户对自己仓库声明的忽略规则，检索功能完全不知道**。

## 决定

新增 `tool/provider/ProjectFileLister` 作为候选文件的唯一出口，三级取值：

1. **git 仓库**：执行 `git ls-files -z --cached --others --exclude-standard`。`--cached` 取已跟踪，`--others` 取未跟踪，`--exclude-standard` 应用 `.gitignore` 与全局 excludes。
2. **非 git 目录 / git 不可用 / 命令失败**：回落到目录遍历，只用硬编码跳过目录兜底。
3. **显式把 `path` 收窄到被忽略目录**：回落遍历，尊重用户意图。

忽略语义**完全交给 git**，本项目不重复实现。

实测效果：597,333 文件 / >10 分 50 秒 → **859 文件 / 282 毫秒**。

## 关键取舍

**自己实现 `.gitignore` 解析（例如用已有的 JGit `IgnoreNode`）。** 否决。要正确处理嵌套 `.gitignore`、否定模式（`!pattern`）、目录专属规则和全局 excludes，本地实现必然在边界情形上与 git 漂移；而漂移的表现是「搜不到本该搜到的文件」，属于静默失败，比慢更糟。已有的 JGit 依赖不构成理由——用它的 API 重新推导一遍语义，仍然是在维护第二份事实源。

**硬依赖 ripgrep。** 否决。引擎不是瓶颈：修文件集是 649 倍收益且零依赖，换引擎只是在同一文件集上的常数倍提速，而 282 毫秒已经足够。此外本机未安装 `rg`，硬依赖外部二进制会带来分发成本。若日后需要，可作为「检测到才用、否则回落」的可选加速，不改变本决定。

**继续扩充硬编码跳过目录。** 只作为非 git 目录的兜底保留，不作为主路径。理由是它无法覆盖用户自定义的忽略规则，且每加一个目录都要在四处同步，正是本次要消除的问题形态。

**子进程输出重定向到临时文件，而不是先 `waitFor` 再读 stdout。** 大仓库下 `git ls-files` 输出可达数 MB，管道缓冲区写满会让 git 阻塞、`waitFor` 永远等不到，形成死锁。沿用 `GitWorktreeBackend.runGit` 的既有范式：重定向到临时文件、`waitFor` 带超时、`finally` 清理。

## 后果

- 检索范围现在由 git 的忽略语义决定。用户修改 `.gitignore` 会立即改变检索范围，这是期望行为，但意味着「某个文件搜不到」的原因可能不在本项目的代码里。
- 显式 `path` 指向被忽略目录时行为与其它 `path` 不同（回落遍历）。这是刻意的，否则会出现「想搜 `Temp/` 却返回空」的陷阱；代价是行为不完全一致，需要在工具描述里说明。
- 引入了对 `git` 子进程的依赖。不可用时回落遍历而不是失败，所以不构成硬前提，但非 git 目录下的检索范围会比 git 目录宽。
- 判断「范围是否整体被忽略」用的是一个启发式：git 文件集在范围内为空、但目录下确有文件时回落遍历。范围本来就是空目录时两种路径结果相同，所以该启发式不会误判。
