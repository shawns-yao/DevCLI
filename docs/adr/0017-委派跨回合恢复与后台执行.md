# 委派记录跨回合保留，续接与后台执行共用隔离归并链路

## 背景

每个用户回合创建独立 DelegationSession，旧报告不能可靠用于下一回合。失败工作区清理后丢失候选修改，耗时子任务阻塞主 Agent，Java 修改也缺少归并前的确定性编译检查。

## 决定

Agent 持有按项目隔离的 DelegationState，保存报告、子任务自身历史与未提交 PatchSet。版本 1 JSON 原子写入私有目录；规则、模型、预算和权限在续接时重新绑定，不持久化父历史、system、reasoning 或图片。

`resume_report_id` 仅允许同角色、原工具和写入范围。补丁在新工作区按原哈希与权限预检，冲突时保留原候选；不重放历史工具调用。提交状态不明或回滚不完整时拒绝恢复。

`run_in_background` 使用有界线程池工厂和现有取消令牌，独立保存状态，通过 `delegate_control` 查询、等待或取消。后台冻结启动回合的规则、Skill、审批意图、权限和预算，期限包含排队；不自动恢复进程重启前的运行任务。

Java 或根级 `pom.xml` 候选通过现有 `PreReviewVerifier`、命令沙箱与主机审批后才允许归并。检查后的候选变化拒绝提交。Reviewer 继续按已有风险信号触发，主 Agent 保留业务验收职责。

## 关键取舍

- 不保存父会话或完整对象图：降低耦合和越权传播，图片及旧运行附件须重新读取。
- 不依赖后台 RunStore 或新增数据库协议：委派生命周期与主会话一致，文件恢复便于显式按 ID 续接；没有后台守护进程或自动重启。
- 复用现有编译验证器：不新增第二套语言探测或测试编排。其他语言、Java 非标准布局及业务效果仍需显式验收。
- 哈希冲突直接拒绝：不对历史失败补丁自动合并；保留候选供人工核对。

## 后果

当前会话缓存最多 64 条、已知记录最多 64MB；单记录 32MB，恢复补丁最多 500 个文件、20MB，单文件 5MB。其他进程历史不做全目录淘汰。历史在循环退出时保存，补丁在工作区清理前保存，不保证强制终止中的修改恢复。

后台最多同时执行 2 个任务、排队 8 个。正常主回合结束不会取消任务，中止、清空历史、切换项目或关闭会取消。编译硬检查增加命令执行成本，环境失败会阻止归并并保留候选。
