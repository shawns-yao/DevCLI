# 非 Git 文件系统级写时复制工作区

## 目标

非 Git 项目不再默认完整复制全部文件。隔离工作区优先共享底层文件数据，同时保持真实操作系统路径，使文件工具、Docker 命令、Pre-Review 和第三方构建工具继续按普通目录工作。

## 方案选择

采用操作系统原生文件克隆，不使用硬链接，也不引入内存文件系统或虚拟文件系统。

- Linux：GNU `cp --reflink=always`。只有底层文件系统确认支持 reflink 时成功，不允许静默退化为普通复制。
- Windows：Windows 11 24H2 / Windows Server 2025 及以上版本且源目录、工作区都位于 ReFS 时，使用系统原生复制操作触发块克隆。
- 其他平台：直接使用复制后端。

Jimfs、Commons VFS 等方案无法把自定义文件系统视图透明提供给任意外部进程。硬链接虽然节省空间，但直接文件写入和外部命令会修改共享 inode，无法满足隔离语义，因此不采用。

## 后端选择

`WorkspaceBackendFactory` 支持四种模式：

- `auto`：Git 项目使用 worktree，非 Git 项目使用写时复制后端。
- `git`：强制 Git worktree。
- `cow`：强制进入写时复制后端；原生克隆不可用时仍安全回退复制。
- `copy`：强制普通复制。

## 安全边界

写时复制物化继续复用统一路径策略：

- 排除 `.git`、`.devcli`、`.idea`、`target`、`build`、`dist`、`node_modules`、`Temp` 和 `Log`。
- 不复制符号链接，禁止路径逃逸。
- 原生克隆完成后逐文件比较源目标 SHA-256；文件缺失或内容不一致视为克隆失败。
- 克隆失败时先删除全部部分结果，再执行有界复制，避免混合两种基线。
- 复制和原生克隆共用超时配置；中断会终止当前物化。
- PatchSet、提交锁、冲突预检、回滚和孤儿清理协议保持不变。

## 能力降级

当前实现将不支持原生克隆视为正常能力差异，不把它当作任务失败：

1. 探测平台、系统版本、文件系统和命令能力。
2. 能力满足时执行原生克隆。
3. 校验克隆结果。
4. 任一阶段失败后清理工作区并完整复制。

因此 NTFS、旧版 Windows、macOS 和不支持 reflink 的 Linux 文件系统仍具备原有隔离能力，只是不获得磁盘和启动性能收益。

## 验证

限定测试覆盖：

- 原生克隆策略成功后的独立写入语义和基线哈希。
- 克隆遗漏文件时清理部分结果并回退复制。
- Windows 版本能力边界。
- Git 与非 Git 的自动后端选择。
- IsolatedWorkspace、WorkspaceExecutionSession、PatchSet 和并发提交回归。

当前开发机 C 盘为 NTFS，只验证了安全回退路径；Btrfs、XFS 和 ReFS 的物理块共享需要在对应文件系统上继续进行现场验证。
